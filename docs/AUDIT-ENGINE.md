# Audit engine

Audits make bounded GET and HEAD requests to public pages. They skip known state-changing paths and browser requests using other methods, but a target may still cause side effects through a GET route or page script. Page discovery stays on the submitted origin, while validated redirects and browser resources may use another public host. The HTTP crawler and browser rendering pass both apply the matching robots.txt rules to requested paths, including redirects and subresources. The crawler applies response and page limits.

## Checks and scores

The engine groups repeated findings and scores Security, Accessibility, Performance, and Search/SEO from 100. Findings reduce their category score according to severity; the four category scores contribute equally to the overall score. Reliability findings also reduce the overall score using the same severity deductions. Repeated linked-page failures are charged per affected URL, up to five URLs per rule.

Page discovery resolves relative links against the document's first `<base href>` when it resolves to HTTP(S), and keeps different paths and query variants separate. Same-origin crawl targets take priority within the bounded link list, so external links cannot consume the entire discovery budget. When link discovery, page count, or crawl depth limits leave known same-origin pages unchecked, the audit is marked Not assessed rather than receiving a whole-site score. Authenticated audit submissions are limited to five per user in a rolling minute; excess submissions are rejected with HTTP 429 before they are queued.

If the HTTP crawler cannot reach an HTML homepage, receives HTTP 400 or higher, receives partial content (HTTP 206), gets an empty response, or finds a generic server-error title or page (including one returned with HTTP 200), the overall score is 0/100 and category scores are marked unassessed. A matching error heading with diagnostic output is also treated as an unavailable homepage. The same applies when the browser does not receive a successful main-document response or does not render visible homepage content; the report identifies the observed response. If any page response exceeds the 1.5 MB scan limit, the audit is Not assessed because not all of its content could be checked. A robots.txt block on the homepage prevents scoring; a blocked linked page or redirect marks the crawl incomplete and also prevents scoring. Deliberately excluded unsafe state-changing routes remain outside the audit scope.

Automated checks cover a subset of possible issues. They are not a security penetration test, accessibility certification, or guarantee of search ranking or performance.
